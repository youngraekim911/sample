# v127 — 보정이 특정 yaml 에만 걸려 있던 문제 + 대역평균 2.1배 가속

한 줄: **v126 의 Green 보정이 `conf/hybrid_lens.yaml` 로 돌릴 때만 걸렸습니다.**
위저드가 만든 yaml 로 돌리면 조용히 빠졌습니다. 보정의 거처를 옮겨 어디서 돌려도
따라오게 했고, 그 김에 대역평균을 2.1배 빠르게 했습니다.

---

## 문제

v126 을 넣고도 Green 이 여전히 높게 나오는 경우가 있었습니다.

**원인** — 위저드가 내보내는 yaml 은 `materials` 를 전부 `{}` 로만 적습니다
(`editors/structure_wizard.html:548`). `measurement` 블록도 아예 없습니다.

```js
materials:{ air:{}, si:{}, oxide:{}, ..., cf_red:{}, cf_green:{}, cf_blue:{}, ... }
```

그런데 v126 은 `k_floor` 를 `conf/hybrid_lens.yaml` 에만 적어뒀습니다.
→ **위저드 경로에서는 보정이 통째로 빠졌습니다.**

| yaml | k 바닥 | 대역평균 | G@500 | G@520 |
|---|---|---|---|---|
| `conf/hybrid_lens.yaml` | 적용 | 20nm | 70.1 | 75.8 |
| 위저드 생성본 (v126) | **빠짐** | **단색** | **76.0** | **76.0** |
| 실측 | | | 70.4 | 74.3 |

이건 "설정을 어디에 두느냐" 의 설계 실수였습니다. UI 로 설정을 받지 않는 것이
이 프로젝트의 원칙인데, 정작 보정을 **한 개의 손으로 쓴 yaml** 에 넣어두면
자동이 아니라 수동이 됩니다.

---

## 고친 것 ① — 보정의 거처를 옮김

### k 바닥 → 물질 파일

k 바닥은 **그 물질의 성질**이지 그 구조의 설정이 아닙니다. 그래서 물질 파일에 둡니다.

`data/materials/cf_green.txt`
```
#! k_floor 0.0105
wavelength n k
   400.0    1.5910    0.1450
   ...
```

- `#!` 로 시작하는 **지시자** 줄. `#` 이라 기존 파서에는 무해합니다
- 측정 행은 그대로 — 실측 데이터는 여전히 안 건드립니다
- 우선순위: **yaml `materials[이름].k_floor` > 물질 파일 `#! k_floor`**
  (yaml 에 `0` 을 적으면 끄는 뜻)

```python
def _k_floor(self, name):
    mconf = self.materials.get(name, {}) or {}
    if "k_floor" in mconf:
        return abs(float(mconf["k_floor"] or 0.0))
    src = mconf.get("src", name)
    if self.matlib:
        return (self.matlib.k_floor(src) if self.matlib.has(src)
                else self.matlib.k_floor(name))
    return None
```

### 측정 대역폭 → 엔진 기본값

`dti.optical` / `collection` 과 같은 자리(`_auto_model_defaults`)에서 자동으로 채웁니다.

```python
QE_BANDWIDTH_NM_DEFAULT = 20.0
QE_BAND_NSUB_DEFAULT = 3
...
meas.setdefault("bandwidth_nm", QE_BANDWIDTH_NM_DEFAULT)
meas.setdefault("n_sub", QE_BAND_NSUB_DEFAULT)
```

yaml 에 적으면 그 값이 이깁니다. `bandwidth_nm: 0` 이면 옛 단색 동작.

### 결과 — 두 경로가 완전히 같아짐

```
    λ      정합 yaml    위저드 yaml 흉내      실측
  500        70.13           70.13          70.40
  520        75.81           75.81          74.34
  540        71.83           71.83          71.50
  550        68.54           68.54          68.90
  560        64.04           64.04          64.50
```

## 고친 것 ② — 대역평균 2.1배 가속

대역평균을 켜면 중심 하나당 `n_sub` 회 solve 라 그대로면 3배가 됩니다.
그런데 **이웃 중심들의 부분 파장은 서로 겹칩니다.**

```
중심 500nm 의 부분파장 :  490  500  510
중심 520nm 의 부분파장 :        510  520  530     <- 510 공유
중심 540nm 의 부분파장 :              530  540  550   <- 530 공유
```

`run_spectrum()` 이 부분 파장을 전부 모아 **중복 제거하고 한 번씩만** 풉니다.
편광도 한 파장 안에서 연달아 풀어 솔버 캐시(λ,θ,φ 키)를 살립니다 — 편광별로
스펙트럼을 따로 돌리면 이 재사용이 깨집니다.

### 측정 (5중심 20nm 간격, nG=101, ds=2)

| | solve 수 | 시간 | |
|---|---|---|---|
| 파장마다 `run_qe` | 32 | 70.1s | |
| **`run_spectrum`** | **24** | **33.3s** | **2.10배** |

값은 **완전히 동일**합니다 (최대 편차 2.2e-14 = 부동소수 잡음).
같은 solve 를 같은 방식으로 평균하므로 당연한 결과이고, 그걸 확인한 것입니다.

중심 간격이 촘촘할수록 더 이득입니다 — 대역 20nm 기준 중심 10nm 간격이면
부분 파장이 거의 전부 공유되어 사실상 공짜입니다.

### 중심은 준비되는 대로 흘려보냄

부분 파장을 오름차순으로 풀기 때문에, 중심 하나에 필요한 부분 파장이 모이는
즉시 확정됩니다. `on_center` 콜백으로 흘려보내 **스펙트럼을 한 점씩 그리는 UI 가
그대로 동작**합니다 (서버 job 의 `rows` 점진 표시 유지).

### 적용한 곳

| 파일 | |
|---|---|
| `src/sim/simulator.py` | `run_spectrum()` 신설, `_avg_outputs()` 분리 |
| `src/sim/runner.py` | `sweep()` 이 `run_spectrum` 사용 |
| `src/api/server.py` | QE job 이 `run_spectrum` + `on_center` 사용 (점진 표시 유지) |
| `tools/compare_measured.py` | 동일 |

**DOE/surrogate 는 그대로 단색입니다** — `run_doe` 는 IR 에서 sim 을 만들어
`qe_bandwidth_nm` 이 0 이고, `sim.run()` 을 직접 부릅니다. 설계 간 *상대* 비교가
목적이고 조건 수가 많아(1065점) 런타임이 지배적이기 때문입니다.
**주의** — 그래서 surrogate 예측값은 `compare_measured` 의 절대값과 밴드에지에서
몇 %p 차이가 납니다. 절대 정합이 필요하면 DOE 결과를 그대로 쓰지 말고
최종 후보만 `run_qe`/`run_spectrum` 으로 다시 확인하세요.

## 회귀 기준값 갱신

k 바닥이 물질 파일로 가면서 **그 물질을 쓰는 모든 구조**에 적용됩니다. 이게 의도입니다.
회귀 fixture 도 `cf_green` 을 쓰므로 기준값이 움직였습니다.

```
EXPECT_G : 0.7341 -> 0.7089
이력: 0.6050(optical=off) → 0.7717(EMT) → 0.7293(η0=0.945)
      → 0.7385(실측 물질 전체) → 0.7341(cf_green 밴드에지 촘촘 측정)
      → 0.7089(cf_green.txt 의 '#! k_floor 0.0105')
```

회귀는 `sim.run()` 을 직접 부르므로 대역폭 기본값에는 영향받지 않습니다.

## 검증

| 항목 | 결과 |
|---|---|
| 위저드 yaml 흉내 vs 정합 yaml | **다섯 파장 전부 소수점까지 동일** |
| `run_spectrum` vs 파장마다 `run_qe` | 최대 편차 **2.2e-14** |

| 회귀 `tests/regress_ir.py` | **ALL PASS** |

| 서버 QE job / runner sweep | 스모크 통과, 점진 표시·csv 정상 |

바닥이 걸린 물질은 **`cf_green` 하나뿐**입니다 (23개 중). `cf_red`/`cf_blue` 는 `None`.
