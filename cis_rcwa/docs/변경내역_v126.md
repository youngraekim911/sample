# v126 — Green 봉우리(+4%p) 원인 규명 및 해결

한 줄: **cf_green 통과대역의 k 가 산란분을 놓치고 있었습니다.** 소광 바닥을
넣으니 봉우리가 사라졌고, 실측 평균오차 2.61 → **2.32 %p** (밝은 채널 2.38 → **1.94**).

---

## 증상

500nm 과 560nm 은 잘 맞는데 **그 사이 520~550nm 만 볼록**했습니다.

| λ(nm) | 시뮬 | 실측 | Δ |
|---|---|---|---|
| 500 | 70.29 | 70.4 | −0.11 ✓ |
| **520** | **78.41** | **74.34** | **+4.07** |
| **540** | **75.33** | **71.5** | **+3.83** |
| 550 | 71.12 | 68.9 | +2.22 |
| 560 | 65.24 | 64.5 | +0.74 |
| 580 | 52.39 | 52.8 | −0.41 ✓ |

---

## 원인 규명

### ① 먼저 — 배분 문제인가, 총량 문제인가

`R + QE_optical + A_stack = 1` 로 분해하고, tetra 픽셀 수 가중 **총수집량**
`(R + 2G + B)/4` 를 실측과 직접 비교했습니다. 이게 결정적이었습니다.

| λ(nm) | 시뮬 총수집 | 실측 총수집 | Δ |
|---|---|---|---|
| 500 | 44.39 | 44.35 | **+0.04** ✓ |
| 550 | 40.29 | 36.80 | **+3.49** ✗ |
| 600 | 35.23 | 35.15 | **+0.08** ✓ |

**총량 자체가 550nm 에서만 초과**였습니다. 즉 채널 간 배분(crosstalk) 문제가
아니라 **그 파장대에서 Si 로 들어오는 빛이 너무 많다**는 뜻입니다.
`A_stack`(Si 밖 손실)도 510nm 에서 48.17% 로 최저 — 손실이 부족한 구간이 명확했습니다.

### ② 무엇이 그 파장대에만 작용하나

모델 안에서 510~560nm 에만 특이한 값을 갖는 건 **cf_green 의 k 골짜기** 하나뿐입니다.

```
cf_green k :  500nm 0.0130  →  520nm 0.0070  →  540nm 0.0060  →  560nm 0.0090  →  580nm 0.0180
                                └──────── 여기가 딱 봉우리 구간 ────────┘
```

### ③ 결정적 증거 — 네 파장에서 독립으로 역산했더니 한 점에 모였다

각 파장에서 "실측에 맞추려면 k 가 얼마여야 하나"를 **서로 독립으로** 계산:

| λ(nm) | 현재 k | 필요 k |
|---|---|---|
| 520 | 0.0070 | **0.0112** |
| 540 | 0.0060 | **0.0103** |
| 550 | 0.0075 | **0.0102** |
| 560 | 0.0090 | **0.0100** |

**네 값이 ±7% 안에 모입니다.** 파장마다 제각각이면 노브를 억지로 맞춘 것이지만,
한 점에 모이면 **파장에 무관한 바닥이 실재한다**는 신호입니다.
그리고 그 바닥(0.0105)보다 k 가 큰 500 / 580 / 600nm 은 자동으로 영향을 안 받습니다
— 실제로 그 세 파장은 원래도 맞고 있었습니다.

### ④ 물리적 해석

안료계 컬러필터의 통과대역 소광에는 두 가지가 섞여 있습니다.

| | 투과 기반 n,k 측정이 잡나 |
|---|---|
| 색소 **흡수** | 잡음 |
| 안료 입자 **산란** | **못 잡음** |

산란으로 정반사 빔에서 빠져나간 빛은 '흡수'로도 '투과'로도 세어지지 않아
k 에 안 들어갑니다. 산란은 파장 의존이 완만해서 **바닥**처럼 보입니다.

### ⑤ 배제한 것들

| 후보 | 왜 아닌가 |
|---|---|
| CF 두께 | 두께 스윕에서 G 피크 감도가 **−0.9%p / +0.10µm** 뿐. −3.8%p 를 만들려면 +0.4µm 필요 (비현실적) |
| 측정 대역폭 | 봉우리를 4%p 누르려면 대역 62nm 필요. 다른 파장이 무너지고, 20nm 가 이미 최소점 |
| crosstalk (DTI) | 총수집량 자체가 초과 — 배분 문제가 아님. 게다가 방향이 반대 |
| 반사 R | 1.4~1.6% 로 평탄, 구간 특이성 없음 |

## 해결

### 코드 — `src/materials/resolver.py`

`materials[이름].k_floor` 를 추가했습니다. 어느 경로(폴더 / dispersion / 상수)로
왔든 마지막에 `k = max(k, k_floor)` 를 적용합니다.

```python
def nk(self, name, lam):
    n, k = self._nk_raw(name, lam)
    kf = (self.materials.get(name, {}) or {}).get("k_floor")
    return (n, max(k, abs(float(kf)))) if kf else (n, k)
```

- **실측 n,k 파일은 안 건드립니다** — `data/materials/cf_green.txt` 원본 그대로
- **물질별 opt-in** — 지정 안 한 물질/구조는 동작이 100% 동일 (회귀 `ALL PASS`, `QE_G@550 = 73.41%` 불변)
- `source()` 진단에도 `+ k바닥 0.0105` 로 표시됩니다

### 설정 — `conf/hybrid_lens.yaml`

```yaml
materials:
  cf_green: {k_floor: 0.0105}
```

## 이 값을 실측값으로 바꾸려면

`k_floor` 는 지금 **역산값**입니다. **적분구(integrating sphere) 측정**으로
산란까지 포함한 총 소광계수를 재면 그 값을 그대로 넣으면 되고, 그러면 역산값이
아니라 실측값이 됩니다. 위치는 `docs/보정값_수정위치.md` 의 ④ 항목입니다.

`cf_red` / `cf_blue` 에는 바닥을 넣지 않았습니다 — 두 채널은 바닥 없이도
맞고 있어(R 피크 −1~+1%p) 근거가 없기 때문입니다. 산란 정도는 안료 종류·입도·
로딩에 따라 다르므로 색마다 다른 것이 오히려 자연스럽습니다.
