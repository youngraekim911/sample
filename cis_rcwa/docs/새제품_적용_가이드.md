# 다른 제품에 적용할 때 — 뭐가 이식되고 뭐가 안 되나

v131 구성의 각 요소는 **누구의 성질인가**에 따라 이식 범위가 다릅니다.

## 이식성 분류

| 요소 | 누구의 성질 | 다른 제품에서 |
|---|---|---|
| RCWA→QE 엔진 (Wood 수정, EMT, 대역평균 등) | **물리/코드** | **그대로 유효** — 독립 TMM 검증 완료, 제품 무관 |
| 물질 n,k 파일 | **물질** | 같은 fab·같은 물질이면 그대로. CF 공급사/배합이 바뀌면 재측정 |
| 산란 바닥 (`src/materials/scatter_model.py` + UI ⚙) | **소프트웨어 보정** | 같은 green CF 를 쓰는 제품이면 **자동 적용** (픽셀 피치가 달라도). 다른 CF 면 UI ⚙ 에서 그 색 값 입력 (적분구 측정/역산으로 결정) |
| `cf_green_device` (구식 — 산란 바닥으로 대체됨) | 물질 | calibrated yaml 전용 기록. 신규 사용 금지 |
| `measurement.bandwidth_nm: 20` | **측정기** | 같은 QE 장비로 재면 제품이 달라도 그대로. 장비가 바뀌면 그 장비 FWHM |
| `coverage: 0.25` | **그 제품의 M1 레이아웃** | **이식 불가** — 제품마다 배선이 다름. 새 레이아웃 면적비 필요 |
| `ild_eff n=1.75` | **그 공정노드의 ILD 스택** | 같은 노드면 유지 가능, 노드가 바뀌면 재확인 |
| `spacer_um: 0.24` | 그 제품 스펙 (실측) | 새 제품의 실측 스펙으로 교체 |

## 설계상 안전장치 — 오염 범위

역산값은 전부 **`conf/hybrid_lens.yaml` + 물질파일 1개(`cf_green_device.txt`)** 에만
있습니다. 엔진/공용 코드에는 하나도 없습니다.

- 새 제품 yaml 을 만들면 **아무 보정 없는 순수 상태**에서 시작합니다
- `cf_green_device` 는 `src:` 로 명시 지정해야만 쓰입니다 — 새 yaml 이 조용히
  물려받는 일 없음
- 위저드로 만든 yaml 도 마찬가지 (보정이 자동으로 따라붙지 않음)

## 새 제품 적용 절차

### 케이스 A — 같은 fab, 같은 CF, 같은 측정기 (파생 제품)
1. 새 구조 yaml 작성 (구조 스펙대로)
2. `cf_green: {src: cf_green_device}` 와 `measurement` 블록은 **가져와도 됨** (물질/장비 성질)
3. BRL(coverage/spacer/n_eff)만 새 제품 BEOL 에 맞게 — 레이아웃 스펙이 있으면 그 값, 없으면 실측 QE 장파장으로 재역산
4. `tools/compare_measured.py` 의 `MEASURED` 표를 새 제품 실측으로 교체 후 검증

### 케이스 B — CF 가 다른 제품
1. 새 CF 의 n,k 측정 필수. **이때 적분구(산란 포함)로 재면** cf_*_device 역산 자체가 불필요해짐
2. 평막 투과로만 재면 통과대역 문제가 재발할 가능성이 큼 — 이건 이 CF 만의 문제가
   아니라 **안료계 CF 평막 측정의 공통 한계**이므로, 색마다 한 번씩 역산(또는 적분구 측정)을 예산에 넣을 것
3. 나머지는 케이스 A 와 동일

### 케이스 C — 측정기가 다른 경우
`bandwidth_nm` 만 그 장비 FWHM 으로. 나머지 무관.

## 역산값을 졸업시키는 길 (제품 무관 시뮬레이터가 되는 조건)

| 역산값 | 이걸 재면 "측정값"이 되어 모든 제품에 그대로 쓰임 |
|---|---|
| cf_green 통과대역 소광 | CF 쿠폰 **적분구 투과** (색마다 1회) |
| coverage | 제품 GDS 의 **M1 면적비** (제품마다 1회, 설계값이라 측정도 아님) |
| ild_eff | 공정노드의 **ILD 필름스택** (산화/질화 두께비, 노드마다 1회) |
| bandwidth_nm | QE 장비 **사양서 FWHM** (장비마다 1회) |

네 개가 다 채워지면 역산값 0개 — 그때부터는 어떤 신제품이든 구조 스펙만 넣으면
예측이 되는 시뮬레이터입니다.

## 예측 신뢰도에 대한 솔직한 경고

지금 상태(역산값 4개 포함)의 신뢰 범위:

- **이 제품 주변의 상대 비교** (DOE/surrogate 로 구조를 조금씩 흔드는 것):
  신뢰 높음 — 역산 항들이 고정된 채 구조 효과만 비교되므로
- **같은 재료·공정의 파생 제품 절대 예측**: 중간 — BRL 항만 재확인하면 됨
- **재료가 다른 제품의 절대 예측**: 낮음 — cf 소광 역산이 무효.
  G 피크 기준 최악 ±4~5%p 의 불확도가 그대로 돌아옴

즉 "실측 없이 신제품 QE 를 절대값으로 맞히는" 시뮬레이터가 되려면 위의
측정 4개가 선행되어야 합니다. 그 전까지는 **calibrate-once-per-platform**
(플랫폼마다 실측 몇 점으로 역산값 갱신) 운영이 정직한 사용법입니다.
