# v128 — v127 전량 원복 (Red QE 이상 보고)

`Red QE 가 이상해졌다`는 보고에 따라 **v127 에서 넣은 것을 전부 되돌렸습니다.**
코드·데이터는 이제 **v126 과 바이트 단위로 동일**합니다.

```
원복한 커밋
  ba42c50  sim: 대역평균 자동화 + 부분파장 재사용으로 2.1배 가속
  c7a99db  materials: k_floor 를 물질 파일로 이관

되돌아간 지점
  c9c83ee  materials: CF 통과대역 k 바닥(k_floor) — Green 봉우리 해결   (= v126)
```

확인: `git diff c9c83ee -- src data tests tools conf` → **차이 없음**

---

## 되돌린 것 ① — 측정 대역폭 자동 적용  ← Red 가 바뀐 원인

**이것이 Red 를 움직인 범인입니다.** v127 은 `_auto_model_defaults()` 에서
대역폭을 자동으로 채웠습니다.

```python
# [삭제됨] src/sim/simulator.py
QE_BANDWIDTH_NM_DEFAULT = 20.0
QE_BAND_NSUB_DEFAULT = 3
...
meas.setdefault("bandwidth_nm", QE_BANDWIDTH_NM_DEFAULT)
meas.setdefault("n_sub", QE_BAND_NSUB_DEFAULT)
```

### 왜 Red 에 영향이 갔나

k 바닥은 `cf_green` 에만 걸었으므로 Red 를 건드릴 수 없습니다. 그런데
**대역폭 자동화는 전 채널·전 파장에 작용합니다.**

대역평균은 QE 곡선을 매끄럽게 만듭니다. 그 효과는 곡률에 비례해서
`(1/2)·f''·W²/12` 만큼 값을 바꿉니다. Red 는 580~620nm 에서 QE 가 30 → 63%
로 급상승하는 구간이라 곡률이 크고, 그래서 이 구간이 눈에 띄게 움직입니다.

즉 "Green 만 고쳤는데 왜 Red 가?" 의 답은 **Green 수정이 아니라 같이 들어간
대역폭 자동화** 였습니다. 두 가지를 한 커밋 묶음에 넣은 것이 잘못이었습니다.

**지금은**: 대역폭은 다시 **yaml 에 적었을 때만** 적용됩니다.
`conf/hybrid_lens.yaml` 에는 `measurement: {bandwidth_nm: 20, n_sub: 3}` 이
그대로 있으므로 그 파일로 돌리면 v126 과 똑같이 동작합니다.
다른 yaml(위저드 생성본 등)은 **단색**으로 계산됩니다 — v126 동작 그대로.

## 되돌린 것 ② — k_floor 를 물질 파일에 두던 것

```
# [삭제됨] data/materials/cf_green.txt
#! k_floor 0.0105
```

```python
# [삭제됨] src/materials/library.py
def k_floor(self, name): ...
#   '#! 키 값' 지시자 파싱, self.meta

# [삭제됨] src/materials/resolver.py
def _k_floor(self, name): ...
#   yaml 우선 -> 물질 파일 폴백
```

**지금은**: `k_floor` 는 다시 **yaml 에 적었을 때만** 동작합니다.
`conf/hybrid_lens.yaml` 의 `materials: {cf_green: {k_floor: 0.0105}}` 는
그대로 있으므로 그 파일로 돌리면 Green 보정이 걸립니다.

부작용도 같이 사라졌습니다 — v127 에서는 물질 파일에 바닥을 두는 바람에
**그 물질을 쓰는 모든 구조**(회귀 fixture 포함)의 값이 움직였습니다.

## 되돌린 것 ③ — `run_spectrum()` 대역평균 가속

```python
# [삭제됨] src/sim/simulator.py
def run_spectrum(self, waves, pols=..., progress=..., on_center=..., cancel=...)
def _avg_outputs(outs, lam0, bandwidth_nm, n)     # run_band() 안으로 되돌림
```

호출부도 원래대로 되돌렸습니다.

| 파일 | 되돌린 내용 |
|---|---|
| `src/sim/runner.py` | `sweep()` 이 다시 파장마다 `run_qe(TE)`, `run_qe(TM)` |
| `src/api/server.py` | QE job 이 다시 파장 루프 (`on_center` 콜백 제거) |
| `tools/compare_measured.py` | 다시 파장마다 `run_qe` |

이 부분은 **값이 바뀌지 않는 순수 속도 개선**이었고(최대 편차 2.2e-14),
Red 이상과 무관합니다. 다만 "그냥 원복" 요청이라 섞어 두지 않고 같이 뺐습니다.
필요하시면 대역폭 자동화 없이 이것만 다시 넣을 수 있습니다.

## 남은 문제 — Green peak 80%

**아직 원인 미확정입니다.** 제가 이 저장소에서 돌린 값과 보고해주신 값이 다릅니다.

| 실행 조건 | G peak |
|---|---|
| `conf/hybrid_lens.yaml`, nG=101, ds=1, 대역 20nm, k바닥 O | **75.8** (@520nm) |
| `conf/hybrid_lens.yaml`, nG=101, ds=2, 단색, k바닥 X | **79.6** (@520nm) |
| 보고해주신 값 | **~80** |
| 실측 | **73~74.3** |

80% 는 **k 바닥이 안 걸리고 대역평균도 꺼진 상태**의 값과 일치합니다.
즉 실행하신 쪽에서 두 보정이 모두 빠져 있을 가능성이 큽니다. 다만 두 번 추측이
빗나갔으므로, 이번엔 확인부터 하고 고치겠습니다.
